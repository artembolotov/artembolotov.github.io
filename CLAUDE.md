# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal site + Russian-language blog of Artem Bolotov (bolotov.dev), built with Jekyll and deployed to GitHub Pages. All content, UI text, and commit-facing copy are in Russian.

## Build and deploy

- There is no Gemfile. The site is built by GitHub Actions (`.github/workflows/jekyll-gh-pages.yml`) using `actions/jekyll-build-pages` (the `github-pages` gem environment) on every push to `main`.
- Local preview requires Jekyll with the `jekyll-seo-tag` and `jekyll-sitemap` plugins (easiest: `gem install github-pages`), then `jekyll serve`.
- No tests, no linters.
- Search is [Pagefind](https://pagefind.app) (Component UI modal; Ctrl/Cmd+K still opens it, but shortcut and keyboard hints are hidden on purpose: `hide-shortcut` on the trigger, modal built without its footer in `default.html`). The workflow runs `npx pagefind` on `_site` after Jekyll; config (excluded page parts) is in `pagefind.yml`. Only published posts are indexed: `default.html` puts `data-pagefind-body` + a `url` meta (canonical URL without `.html`) + an explicit `image` meta (front matter `image`; this stops Pagefind from auto-capturing the first post image's `alt` as searchable `image_alt`, which surfaced posts for words invisible on the page) on `<main>` for `layout: post` without `draft: true`. The trigger lives in `_includes/tag-menu.html`; theme variables (`--pf-*`, incl. dark) are in `blog.css`, and so are overrides of its component styles (iOS-like filled input, icon clear button, borderless result list): they repeat Pagefind's own specificity prefix (`:is(*, #\#)` three times), which wins because `blog.css` loads later. Excerpts stay one line; `scripts/search.js` trims their start so the highlighted match is visible (Pagefind centers it in a 30-word window). The same script mirrors `window.visualViewport` into `--search-vh`/`--search-top`, which `blog.css` uses to size the modal, so the iOS keyboard doesn't cover results; since iOS fires the viewport resize only after the keyboard animation, it resizes early on input focus/blur using the last measured keyboard height (Safari supports neither `interactive-widget`, which is in the viewport meta for Android/future Safari, nor `env(keyboard-inset-*)`). On phones `blog.css` also locks page scroll while the modal is open (`html:has(dialog.pf-modal[open])`, since WebKit ignores the dialog's `overscroll-behavior`) and paints the backdrop in the modal color so nothing shows through the translucent iOS keyboard. The lock alone does not stop iOS: with the keyboard open it pans the visual viewport on drags the results list cannot take (empty modal before the first search, the header, the list ends), so `search.js` cancels exactly those `touchmove`s (non-passive listener on `pagefind-modal`; the input is exempt for caret dragging). Hiding the keyboard on drag was tried and rejected. New UI text inside posts that shouldn't be searchable goes into `exclude_selectors` in `pagefind.yml`. The Component UI is kept off the critical path: its CSS loads non-blocking (`media="print"` + `onload` in `default.html`, which also adds `html.pf-ready`; until then `blog.css` hides the trigger), and `search.js` injects its JS module after `load` at idle time, or right away on pointerdown/focus on the trigger or Ctrl/Cmd+K. The trigger in `tag-menu.html` contains a static copy of the button the component renders (keep it in sync when upgrading Pagefind), so it's visible and clickable before the module arrives; an early click or Ctrl/Cmd+K opens the modal once it's defined. Pure on-demand loading was rejected: iOS raises the keyboard only for focus inside the tap itself. `/pagefind/` exists only in the CI build, so under plain `jekyll serve` the trigger stays hidden; to try search locally run `jekyll build` then `npx pagefind --serve`.
- `future: true` in `_config.yml`: future-dated posts are built and published.

## Content model

- Posts live in `blog/_posts/` (not the root `_posts/`, which is empty). Filename date defines the URL: `/blog/:year/:month/:day/:title`.
- Post front matter: `title`, `description`, `tags` (plus defaults from `_config.yml`: layout `post`, author, image).
- **Drafts are a custom convention, not Jekyll drafts**: `draft: true` in front matter. The post still builds (its URL is live), but listing pages, `sitemap.xml` and `feed.xml` skip it, `default.html` adds `<meta name="robots" content="noindex">` (same for any page with `noindex: true`, e.g. `404.html`), and series pages show it greyed-out as "выйдет <date>" (`.article-upcoming`).
- SEO: `sitemap.xml` and `feed.xml` (Atom, full text) are hand-written Liquid templates, not plugins; the sitemap lists a tag page only once it has a published post. When a published post is substantially updated, add `last_modified_at: YYYY-MM-DD` to its front matter: it feeds `dateModified`, sitemap `lastmod` and the feed's `updated`. Post author data for jekyll-seo-tag (url, X account) is in `_data/authors.yml`; `logo` is deliberately not set in `_config.yml` (it would make the publisher an Organization). `robots.txt` is a single `User-agent: *` group on purpose — a crawler obeys only its most specific group.
- Tags double as sections. Each tag has a landing page `blog/<tag>/index.html` with layout `tag-page`; `series: true` in its front matter switches the layout to a numbered series listing (e.g. `blog/internet/` — the "Внутри интернета" series). Russian tag labels come from `_data/tag_translations.yml` via `_includes/tag-translations.html`; the top tag menu is a hardcoded list in `_includes/tag-menu.html`.
- The root `index.html` is a standalone single-page personal site, unrelated to the blog machinery (no front matter, no Liquid): its title, meta, Open Graph and `Person` JSON-LD are hand-written in its `<head>`. The header photo comes in AVIF/WebP/JPEG (`img/bg-tall.*` for phones, `img/bg-wide.*` from 768px) via `image-set()` in `styles/main.css`, and the AVIF is also preloaded in `index.html`, so a new photo means updating both. Timeline pictures are WebP at 1x/2x/3x with `loading="lazy"` (their size is fixed in CSS, so no layout shift). Bump the `?v=` on `main.css` when changing it.

## Layouts and styles

- Layout chain: `compress` ← `default` ← `post` / `tag-page`. `default.html` contains the whole page shell (nav, logo) and loads all CSS/JS. Scripts go in `<head>` with `defer`; site scripts come before the third-party `gdeya.bolotov.dev` loader, because deferred scripts run in order and a slow external one would hold ours back.
- CSS is plain, no preprocessor: `styles/all.css` (base + nav, loaded everywhere), `styles/main.css` (homepage only), `styles/blog.css` (shared blog components: galleries, code highlighting, author footer...). New shared component styles go into `blog.css` by convention, including plain Markdown tables (`main > table`: hairline rows, grey small header, edges flush with the text).
- Page-specific stylesheets are opt-in via front matter (see the `page.styles` loop in `default.html`): each name in `styles:` loads `/styles/<name>.css`. Interactive elements of the `internet` series are split into a shared framework (`styles/internet.css`) plus one file per component (`styles/internet-<include-name>.css`); a post using a component lists both, e.g. `styles: [internet, internet-dns-lookup]`.
- Dark theme is handled via `@media (prefers-color-scheme: dark)` blocks in each stylesheet — every new component needs one. Accent colors: `#0089ff` (dark: `#64b2ff`), hover red `#f41224` (dark: `#ff453a`).
- `html.no-js` class is removed by an inline script in `default.html`; use it for no-JavaScript fallbacks (see galleries).

## Includes (components)

- `img.html` — single image; bare filenames auto-resolve to `/blog/img/<post-slug>/<file>`.
- `gallery.html` + `scripts/gallery.js` (loaded globally). Gallery images with a size (`file|alt|WxH`) get a `srcset` of downscaled copies `name@480w.webp`/`name@720w.webp`: CI generates them before the Jekyll build (`.github/scripts/gallery-variants.cjs`, widths and the row height used for `sizes` in `_data/gallery_variants.json`), they're gitignored, and the include lists only copies found in `site.static_files`, so plain `jekyll serve` simply has no `srcset`. Lines without a size get no `srcset`.
- Other includes: `youtube.html`, `code-block.html`, `reading-time.html`, `author-footer.html`.
- Series-specific interactive components live in subfolders named after the series tag, e.g. `_includes/internet/live-editor.html` (self-contained markup + inline JS; styles are in `styles/internet-<include-name>.css` on top of the `styles/internet.css` framework, loaded via `styles:` front matter).
- All `internet` simulators share the `sim-*` framework classes defined in `styles/internet.css`: `sim-window`/`sim-head`/`sim-title` shell, `sim-label`, `sim-actors`/`sim-actor` status pills, `sim-choices`/`sim-choice` action buttons, `sim-btn`/`sim-btn--ghost`, and the chat log `sim-log`/`sim-step` with `--right`/`--result`/`--explain`/`--hint` modifiers (dark theme included). New components should reuse these and keep only unique styles under their own prefix.

## HTML compression caveats

`compress_html` (see `_config.yml`) processes all output except in the `development` environment:
- HTML comments (`<!-- ... -->`) are stripped — don't rely on them at runtime.
- Blank lines are removed, but newlines within non-blank lines survive, so inline `<script>` blocks with `//` comments are safe; just avoid meaningful blank lines outside `<pre>`.

## Markdown conventions in posts

- External links: `[text](url){:target="_blank" rel="noopener"}` (kramdown IAL).
- Ordered lists use repeated `1.` markers.
- iOS Safari quirk to respect in interactive elements: form fields need `font-size: 16px`+ on mobile to avoid focus auto-zoom (see `.live-editor-input`).
- **Liquid runs over the whole `.md` file before kramdown, including inside fenced/inline code.** Any literal double-curly-brace or curly-percent template syntax in example code (GitHub Actions `${{ vars.X }}` / `${{ secrets.X }}`, Jinja, other templating) gets parsed as a Liquid tag and silently swallowed/emptied, or breaks the build outright if malformed — it does NOT render as-is just because it's in a code block. Wrap such snippets in Liquid's raw block (whole fenced block, or inline around a single `${{ ... }}` span). See [blog/_posts/2026-08-24-git-push-deploy.md](blog/_posts/2026-08-24-git-push-deploy.md) for both cases. When adding or editing a post with example code, grep it for `{{` / `${{` before publishing. This file itself is Liquid-rendered by `jekyll-optional-front-matter` (it's excluded in `_config.yml`, but stay wary if editing that) — never write literal `${{`/`{%` template syntax here either.
